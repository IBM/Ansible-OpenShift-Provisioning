Step 2: Set Variables (group_vars)#

Overview#

  • In a text editor of your choice, open the template of the environment variables file. Make a copy of it called all.yaml and paste it into the same directory with its template.
  • all.yaml is your master variables file and you will likely reference it many times throughout the process. The default inventory can be found at inventories/default.
  • The variables marked with an X are required to be filled in. Many values are pre-filled or are optional. Optional values are commented out; in order to use them, remove the # and fill them in.
  • This is the most important step in the process. Take the time to make sure everything here is correct.
  • Note on YAML syntax: Only the lowest value in each hierarchicy needs to be filled in. For example, at the top of the variables file env and z don't need to be filled in, but the cpc_name does. There are X's where input is required to help you with this.
  • Scroll the table to the right to see examples for each variable.

13 - (Optional) Create compute node in a day-2 operation#

The day-2 workflow now uses a host_vars-based model.

For a single-node day-2 operation, day2_compute_node must be a list of host_vars entry names. Each entry must match a file in inventories/default/host_vars.

Example in all.yaml:

day2_compute_node:
  - example-day2-node

The referenced host_vars file contains the actual node and hypervisor definition. Use: - inventories/default/host_vars/compute-day2.yaml.template as the template - inventories/default/host_vars/example-day2-node.yaml as an example

How day2_compute_node is used#

day2_compute_node is consumed by several playbooks:

  • playbooks/0_setup.yaml loads the referenced host_vars files and generates the day2_hosts inventory section for eligible hypervisors.
  • playbooks/3_setup_kvm_host.yaml configures the hypervisors listed in day2_hosts when setup_host: true.
  • playbooks/create_compute_node.yaml loads the first entry from day2_compute_node and creates the node.
  • playbooks/delete_compute_node.yaml loads the same host_vars entry when deleting a day-2 node.

Notes for multi-node day-2 operations#

playbooks/create_multiple_compute_nodes.yaml does not use day2_compute_node directly. Instead, it expects an extra-vars file containing day2_compute_nodes, which is also a list of host_vars entry names.

Example:

day2_compute_nodes:
  - example-day2-node
  - another-day2-node

If those nodes use new hypervisors that must be prepared first, temporarily add the relevant host_vars entry names to day2_compute_node, rerun playbooks/0_setup.yaml, and then run playbooks/3_setup_kvm_host.yaml.
